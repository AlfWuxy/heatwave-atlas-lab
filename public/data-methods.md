# 网站数据口径与复现

2026-09-27。本文说明公众网站的已实现数据产品。它与区域论文的拟定协议分开，不宣称已完成长江区域机制诊断、因果归因或全球全量热浪目录。

## 覆盖、来源与获取

网站包括六个坐标附近 ERA5 网格的 2006-01-01—2025-12-31 日最高、日最低 2 米气温，每点 7,305 日、共 43,830 日；波特兰、巴黎、重庆三个短窗口共 1,152 个小时，含九项天气变量。坐标覆盖六个地方，不能代表各国平均或全球趋势。城市名是帮助公众定位的标签。

原始再分析为 ECMWF/Copernicus ERA5；当前通过 **Open-Meteo 第三方历史 API** 取得，而非从官方 CDS 直接下载。固定 `models=era5`、`elevation=nan`、`cell_selection=nearest`、`timezone=UTC`、`wind_speed_unit=ms`。所有值属于返回网格，不是城市官方站点实测。网格坐标与请求坐标在 JSON 和来源 CSV 中分列保存。

样本主数据于 2026-09-26 下载，网站新增的 1991—2005 年基准补充数据于 2026-09-27 下载；2006—2020 年部分直接复用已有样本。各次精确时间、请求 URL、返回网格、单位、原始字节 SHA-256 均保存在清单中。不能把网站生成日当作全部原始数据的下载日期。

官方/原提供方说明：[ERA5 官方数据集](https://cds.climate.copernicus.eu/datasets/reanalysis-era5-single-levels?tab=overview)、[Open-Meteo 历史 API](https://open-meteo.com/en/docs/historical-weather-api)、[数据归属](https://open-meteo.com/en/licence)、[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。

## 时间与变量

- 日最高/最低值按 **UTC 日**聚合；日期标签不能直接改成城市当地日。当地日极值需要重取或用完整逐小时数据重算。
- 逐小时 JSON 使用带 `Z` 的 ISO 时间，仍可单独显示当地时间；数值与原始 UTC 时刻一一对应。
- 气温：°C；相对湿度：%；海平面气压：hPa；云量：%；向下短波辐射：W/m²；10 米风速：m/s；风向：°；0—7 cm 土壤体积含水量：m³/m³；降水：mm。
- `shortwave_radiation` 是 API 定义的前一小时平均向下短波辐射；降水是前一小时降水总量。这些字段不能与同时间戳瞬时气温无区别地解释为瞬时收支。
- 气温不等于热量或地表温度。土壤含水量不等于蒸散；海平面高气压不单独证明高空脊或下沉。当前样本缺少完整净辐射、感热、潜热、高空环流等，不能分解“每种机制贡献百分比”。

## 年度汇总

`maxTmax` 是当年日最高温度中的最大值；`maxTmaxDate` 取第一次出现该最大值的 UTC 日期。`meanTmax` 是当年逐日日最高气温的算术平均，**不是年平均气温**。`meanTmin` 同理。未使用 `(Tmax+Tmin)/2` 冒充逐小时平均气温。`minTmin` 是年内日最低值的最小值。

图表比较相同点位、相同变量与相同口径；网站不拟合全球变暖趋势，不将六点平均称为全球平均，不对气候变化做新的事件归因。

## 自定义点位高温过程与异常

只有该点位 1991-01-01—2020-12-31 共 10,958 日完整且网格一致时，`baseline.status` 才为 `available`；否则所有异常/计数为空，不以零替代未知。

1. 基准采用 1991—2020 年。对每个日历日，取其前后各 15 日，共 31 个日历日；跨年循环，形成 30 × 31 = 930 个 Tmax/Tmin 值。
2. 抽样池排除 2 月 29 日。2 月 29 日的基准均值和 P90 取 2 月 28 日与 3 月 1 日的平均。
3. 基准均值分别计算 Tmax、Tmin 的 930 值算术平均。P90 采用 Type 7 线性插值分位数。
4. 日 Tmax 异常 = 当日 Tmax − 对应日历日的基准 Tmax 均值；它不是“超过 P90 的幅度”。年度 `meanTmaxAnomaly` 为当年逐日该异常的平均。
5. 暖季预设北半球 5—9 月、南半球 11—3 月。严格满足 `Tmax > P90` 且连续至少三个 UTC 日，才形成一个过程；不合并间隔一天的两段过程。北印度的春季高温等可能被这个简化季节窗口遗漏，因此该指标用于透明探索，不能声称覆盖当地全部高温。
6. `hotSpellDays` 按每个日历年内实际符合过程定义的日子计数；`hotSpellCount` 按过程开始年份计数。南半球跨年过程只计一次，天数可以分属两年。碰到研究期首尾的过程以 `touchesStudyBoundary` 标记，真实持续时间可能更长。
7. 该定义由网站选择，不是当地预警标准，也不是 WMO 统一热浪定义。它不等于常见 WSDI 指数（后者另有持续时间/参考期/窗口规定）。

这里是探索性描述。研究期与基准期重叠，尚未进行标准指数趋势分析中可能需要的样本内百分位自举校正。因此不能从这些事件数直接声称有统计显著趋势、风险倍增或气候变化贡献。比较需连同阈值、季节、格点与时间口径阅读。[Climdex 指标定义](https://www.climdex.org/learn/indices/)

这些是人工选定、用于观察过程的时间窗口，不是阈值算法识别出的热浪起止。单点序列不能说明全区域最高温或影响人数。网站对“真实曲线”“文献支持的机制解释”“理想化教学实验”应持续区分。

## 区域风温地图

新增三个有限区域、0.25°格距的逐小时风温场：重庆—四川425点×456小时，巴黎周边525点×312小时，波特兰周边525点×384小时。每帧含2米气温以及根据10米风速、风来向重建的u/v；合计559,200个格点小时，不能称为全球全量资料。逐值验证与原始响应清单独立保存在 `data/regional/`；公开JSON对应 `public/data/regional-<id>.json`，来源和哈希见同名 `-manifest.json`。

地图将所选小时风场中的示踪粒子与绝对气温色面叠加，按经纬度节点双线性插值。没有计算热量形成的完整收支；10米风与2米气温并非同高度，动画也不表示连续气块历史轨迹。固定12—42°C色标在两端饱和，蓝色不等于气候异常。地图时间轴与代表点曲线共用同一UTC小时。底图为当前OpenStreetMap地理背景，署名在地图内保留。实现、字段和限制详见 [区域风温回放方法](regional-methods.md)（公开下载文件）。

## 公开数据合同

- `atlas.json`：`{schemaVersion, generatedAt, scope, source, cities:[...]}`。每城含坐标、年份范围、20 个 `annual` 汇总、`baseline`、`events`、日数据下载链接与原始获取时间。
- `daily-<city>.json`：`rows:[{time,tmax,tmin,baselineTmax,baselineTmin,p90Tmax,tmaxAnomaly,isHotSpellDay}]`，含字段单位和基准说明。
- `climatology-<city>.json`：366 个日历日的均值、P90 与基准抽样说明。
- `baseline-<city>-1991-2020.csv`：每点完整 10,958 日基准原始日最高/最低气温，供重新计算阈值；链接在 `baselineCsvUrl`。
- `cases.json`：三例元数据、峰值、时间范围、数据地址、原始来源和哈希。
- `case-<id>.json`：完整 case 元数据、`units` 以及逐小时 `rows`；所有九个数值保留 API 原精度。
- 同名 `.csv`：可下载数据表；`annual-summary.csv` 为 120 行年度汇总；`sources.csv` 与 `sources.json` 为原始请求来源表。
- `download-manifest.json/csv`：公开文件的字节数与 SHA-256。`validation.json`：实际连续性、哈希、逐值复核和算法边界检查结果。

## 复现与检查

在项目根目录运行：

```sh
python3 scripts/fetch_site_reference.py
python3 scripts/build_site_data.py
```

下载按年份串行缓存，HTTP 429 立即停止；不以换身份、并发端点等方式规避限额。缓存只有路径、URL、SHA-256 同时一致才复用。构建仅读取主样本和追加数据，不改写主样本原始文件。

构建时验证：原始文件哈希、唯一且连续时间、同网格、有限数值、Tmax≥Tmin、单位；重新读取公开 JSON/CSV 并逐值比对原始 Tmax/Tmin，重新逐值比对小时字段；用独立的分位数函数复核日历阈值样点，并测试严格阈值、最短三日与暖季筛选边界。这些检查保证转换过程可追溯，不能代替独立观测验证或科学因果证据。
