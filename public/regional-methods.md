# 区域风温回放：数据、显示与边界

版本：2026-09-27。真实案例地图使用历史再分析场；独立的“粒子热场”页面仍是无量纲教学实验。二者不共用物理模型。

## 这张地图回答什么

在给定时刻，哪里较热、哪里较冷，近地面水平风朝哪里吹，以及这些场随小时怎样改变。图层不是新计算的天气预报、热浪归因或热量收支。天气数据经 Open-Meteo Historical Weather API 取得，底层指定 ECMWF / Copernicus ERA5；不是气象站实测，也不是本站直接从 CDS 下载的原生风分量。

## 有限区域与时间窗口

| 案例 | 经度（向东为正） | 纬度 | 格点 | UTC窗口 | 小时 |
|---|---|---|---:|---|---:|
| 重庆—四川 2022 | 103°E—109°E | 28°N—32°N | 25×17 = 425 | 2022-08-10—08-28 | 456 |
| 巴黎周边 2019 | 1°W—5°E | 46°N—51°N | 25×21 = 525 | 2019-07-18—07-30 | 312 |
| 波特兰周边 2021 | 125°W—119°W | 43°N—48°N | 25×21 = 525 | 2021-06-20—07-05 | 384 |

范围是为首版展示选取的矩形，不是热浪影响边界。上述三例合计1,475个空间节点、559,200个格点小时，每个格点小时含温度与两项风分量；它不是全球20年完整网格库。完成状态以各案例来源清单 `status` 和公开数据文件为准。

原始经纬度网格间距0.25°，约28 km南北间隔；东西距离随纬度变化。放大地图、增加粒子和插值不会产生街区级信息。当前支持不跨日期变更线、位于Web Mercator纬度范围内的区域。

## 取数与可复核性

固定 `models=era5`、`cell_selection=nearest`、`timezone=UTC`、`wind_speed_unit=ms`；逐坐标设置 `elevation=nan` 关闭海拔降尺度。API字段为 `temperature_2m`、`wind_speed_10m`、`wind_direction_10m`。

原始响应按批保存在 `data/regional/<id>/raw/`。清单保存请求URL、请求与返回坐标、UTC获取时间、响应字节数与SHA-256，以及公开结果哈希。脚本拒绝重复格点、坐标偏移、不连续时间、缺测和错误单位；不把缺值补零。所有点通过后才发布该例JSON。

每次先做2点预检，随后每批至多25点、串行访问且响应后间隔至少8秒；HTTP 429立即停止，5xx最多重试一次，不通过并发或换入口避开限额。缓存仅在URL和字节哈希同时一致时复用。

```sh
python3 scripts/fetch_regional_data.py --case all
node --test tests/regional-data.test.mjs
node --test tests/regional-field.test.mjs
npm run build
```

公开数据 `/data/regional-<id>.json` 中，经纬度均升序，帧数组 `index=j*nx+i`；先从西到东，再从南到北。`times` 是带Z的UTC时刻，与原有代表格点曲线一一对齐；切换当地时钟仅改变显示标签。

## 温度与风如何进入画面

温度是2米气温，单位°C。API气象风向表示风从哪里来，以正北0°、正东90°递增；转换为向东分量u、向北分量v：

```text
u = -speed × sin(direction × π/180)
v = -speed × cos(direction × π/180)
```

分量保留六位小数，仅用于减少后续舍入；原风速和风向已有API输出精度限制，不能把重建分量称为ERA5原生u/v。零风速时不赋予可解释的来向。

连续色面和粒子采样在原始节点之间作经纬度双线性插值；画面先从Mercator坐标反算纬度，避免误把屏幕高度当成等纬度间隔。点击地图读取最近的**原始节点**，明确展示坐标、2米气温、10米风速与来向。区域外不外推气象值。

固定色标为12°C蓝、27°C浅灰、42°C红，区间外饱和；所有案例共用同一色标，便于比较。数字读数保留实际值，所以例如43.3°C仍显示43.3°C。蓝色仅表示色标中的较低气温，不是相对常年的异常；本图未计算区域气候基准。粒子颜色与色面都采用此绝对温标；教学实验的红蓝则是无量纲温度异常，口径不同。

## 粒子时间与地理位移

粒子在**选中小时的固定风场**中推进，展示近似流向。经纬度速度由球面地理距离换算，u向东、v向北，并以中点法近似推进；不添加热箱浮力、闭合墙壁或虚构涡流。粒子越出数据矩形或达到显示寿命后重新播种，不反弹。

动画按1显示秒约等于7,200秒风场位移压缩。为稳定绘制，长卡顿和后台恢复不追赶；低帧率会影响视觉时长，因此画面不是可用于计时测速的分析仪器。粒子尾迹只是近期显示位置的短拖尾，不是事件期间可追溯的气块路径。

“播放地图时间回放”按小时切换真实资料，并同步下方曲线；1×、3×、6×为日期推进速度。“播放/暂停风场动画”独立控制当前风场中的流动。当小时改变，粒子重新播种并清除旧拖尾；没有把不同小时的粒子连成历史轨迹。桌面默认32,768粒子，小屏初始化为8,192；数量不影响天气场分辨率。

系统选择减少动态效果时默认暂停风场，可手动播放。地图离开可视区域、页面后台时暂停粒子绘制。关闭粒子仍可读色面和数值；关闭温度层可单看风向。WebGL初始化失败会说明原因，原有曲线与数据下载仍可独立使用。

## 为什么还不能回答全部热量来源

10米风与2米气温处于不同高度；让粒子随风移动并按当地温度重新着色，不表示它携带同一份热量，更不表示空气分子轨迹。它没有闭合温度倾向方程，没有算感热、潜热、净辐射、垂直运动、绝热压缩或完整边界层交换。近地面暖区与风向同时出现也不证明平流是主因。

进一步研究可在同一事件窗口加入高空环流、垂直速度和地表能量项，明确时间平均、层次与单位，分析温度倾向及残差，并用独立观测核对。这是后续研究步骤，本站当前不输出机制贡献比例或因果结论。

## 地图、托管与署名

引擎采用MapLibre GL JS；区域底图是OpenStreetMap当前地理背景，不是事件当年的遥感影像。底图缩放不改变气象网格，也不代表历史地表利用情况。世界案例概览仍使用Natural Earth/world-atlas，两类底图分别署名。

本版只按浏览器可视范围加载标准 `https://tile.openstreetmap.org/{z}/{x}/{y}.png`，保留地图内署名、浏览器缓存与Referer。不预抓取、不批量离线下载瓦片。标准公共瓦片服务没有本项目的专属容量保障，公开访问量增长时应换用合适的瓦片服务或自托管，并同步更新署名与站点CSP。

气象数据：ECMWF / Copernicus ERA5，经Open-Meteo提供；按Open-Meteo数据的CC BY 4.0要求署名。整理、风分量转换和插值由本站完成。OSM数据遵循其版权与ODbL说明；MapLibre代码保留其开源许可。前端及Web Worker由本站构建，不需要地图API密钥；数据静态托管，用户浏览不会触发实时气象API请求。
